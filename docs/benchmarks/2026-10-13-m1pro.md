# Thumbnail benchmarks, 2026-10-13

**Machine:** MacBook Pro, Apple M1 Pro (8 performance + 2 efficiency cores
reported as 8 by `available_parallelism`), 32 GB, macOS 27.2, internal
Apple Fabric SSD. **Build:** `cargo build --release` (opt-level 3, thin
LTO). **Command:** `pw bench <dir> --size 320 [--cache] [--threads N]
[--recursive]`. Each row is one run; no repetitions, so treat differences
under ~20 % as noise.

**Methodology caveats, read before quoting:**

* "Cold" means the thumbnail cache was empty. The OS page cache was warm
  in every run (the files had been read minutes earlier and this session
  could not purge it without sudo). A true cold-disk run will be slower.
* The 300-NEF folder is 100 hard links to each of three D850 files, so I/O
  is trivially cached and only decode and metadata work is measured.
* Everything is internal SSD. No card-reader, USB or network runs.
* `per item` is per-file latency inside the parallel loop, so p50 under 8
  threads includes contention; the 1-thread run shows the pure cost.

## Reading the numbers

* A NEF thumbnail costs **~4.3 ms of CPU** (1-thread p50): mmap, IFD walk,
  pick the 1620 px MakerNote/SubIFD preview, 1/4-scale DCT decode, box
  filter, JPEG-encode for cache. Eight threads give ~1 ms/item wall.
* A **2048 px camera JPEG costs 5× more than a 55 MB NEF** (25 ms vs
  4–7 ms) because the JPEG itself is the only preview and must be decoded
  at 1/2 scale (1024 px) to reach 640 px for a 320 px thumb. Camera JPEGs
  with an Exif thumbnail are not helped: those are 160 px. A larger
  embedded preview would be used if present.
* Warm cache is **~1.5–1.8 ms/item**, dominated by reading and decoding a
  ~20 KB cached JPEG. A 1 000-item folder re-opens in ~0.3 s of decode.
* The max latencies (97 ms NEF, 649 ms JPEG) are single large files and
  cache-directory creation; they do not block the UI thread.

## Not measured yet

Time to first visible thumbnail in the GUI; frame time while scrolling;
image-to-image latency in preview mode; memory under scrolling with
eviction; behaviour on a card reader; HEIC/CR3 (unsupported); true
cold-disk open. The status bar now shows frame time and texture-upload
counts to make the first three measurable by hand.
